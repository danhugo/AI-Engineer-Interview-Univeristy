# buffer sized from config — this is how many batches stay buffered ahead
buf = max(1, self.prefetch_factor * self.num_workers)
bg = WorkerPool(
    dataset=self.dataset,
    collate_fn=self.collate_fn,
    num_workers=self.num_workers,
    buffer=buf,
)
try:
    bg.start(batch_index_lists())   # feed index lists, spawn workers
    for batch in bg:             # consume prepared batches (backpressure-aware)
        yield batch

Two queues, opposite directions. index_q (left) carries tiny index lists from main to workers — all queued up front by start(). Workers pull one, fetch dataset[i], collate, and put the prepared batch into batch_q (right). That queue is bounded to buf = prefetch_factor × num_workers = 4. Backpressure: when batch_q is full, a worker put() blocks (red ⚠) — it does not pile up unbounded batches in RAM. The main loop for batch in bg pulls one batch at a time, freeing a slot so a blocked worker can proceed.
